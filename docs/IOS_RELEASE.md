# Pulse iOS release status

The iOS workflow generates the Flutter runner, applies the original Pulse app icon, adds camera/microphone/photo permissions, analyzes Dart, runs widget tests and builds an unsigned release app. Its artifact is Pulse-iOS-Unsigned. An unsigned Runner.app is not an installable IPA.

## Apple setup required
1. Enroll an Apple Developer team and register the app identifier generated by Flutter: com.pulsemessenger.pulseMessenger. Confirm the actual PRODUCT_BUNDLE_IDENTIFIER in Runner.xcodeproj before creating provisioning profiles.
2. On a Mac, open ios/Runner.xcworkspace after scripts/bootstrap_ios.py and flutter pub get. Select Runner, choose your team in Signing & Capabilities and confirm a unique bundle identifier.
3. Configure public Supabase build values from config.example.json. Never add LiveKit, payment or Supabase service-role secrets to this file.
4. Run on a physical iPhone. Test camera/microphone/photo permission acceptance and denial, login, chat, playback, WebRTC and LiveKit with a second device.
5. Archive a signed Release build in Xcode and upload through Organizer to TestFlight. Complete App Store privacy disclosures before review.

## Implemented and remaining
Local notification permission is requested only when enabled in settings. iOS local alerts use Darwin notification details. Test notification taps on a physical device.

Closed-app push and system incoming-call UI require separate iOS Firebase/APNs/CallKit work; the current push client remains Android-only. No APNs credentials or Apple signing identity are configured by this workflow.

NativePulseEditor currently provides Android/Windows export. iOS video trimming, style export, avatar rendering and watermarked downloads still require an AVFoundation implementation. Do not describe this compile artifact as full feature parity or a completed App Store release.

The original favicon is retained. Seasonal branding changes in-app assets only, not the installed iOS app icon.
