# Pulse 0.5.3 — channel media, status covers and moving download watermark

This is a cumulative update to the existing native Flutter Android/Windows project. Accounts, chats, message requests, groups, profiles, staff verification, Premium/redemption records, icon navigation, wallpapers and prior LIVE Party source are preserved. Read 0.5.2/0.5.1 notes for earlier changes and limitations.

## What changed

- Administrators can publish photo, video and recorded voice-note announcements in channels. The attachment menu beside the channel composer opens a media screen with a real preview and optional caption. Photos/videos use the existing editing Studio; videos can choose a cover frame. Audio uses the existing microphone recorder, duration and waveform. Members can view/react but cannot upload or publish.
- Uploads use the existing native resumable transport with the channel bucket explicitly selected. Progress updates while bytes transfer; publishing completes after upload. Existing free allowance (500 MiB per file) and Premium maximum (2 GiB) remain. Files over the free allowance open the Premium screen before editing/upload. Hosting limits remain independent: a Free Supabase project cannot accept files over its configured global maximum. Failed/unpublished uploads receive best-effort cleanup; there is no process-restart draft/upload recovery or background orphan sweeper.
- Channel history/search now runs on the server, with a full-text index and stable timestamp/ID pagination in pages of 30. Search matches words in announcement captions, including older posts. It is not an arbitrary substring search and does not transcribe voice or video content. Older pages load while scrolling or with the explicit retry/load button. Polling does not discard older loaded pages. Searching or browsing older messages does not automatically clear all unread counts.
- Channel information shows actual follower/media counts, follow/unfollow, editing for admins, search and media history. The main screen retains the compact photo/name header, rounded bubbles and reactions below them. Video covers open an embedded player when tapped; photos load as images and voice notes have playback/waveform controls. No fake mute/share buttons are added.
- New video statuses use the existing Video Studio to choose a cover frame. The cover is stored privately and has the same audience/24-hour expiration as the status. Older video statuses without a saved cover retain their video indicator/background. Status video files remain limited to 20 MiB; JPEG covers must be at most 2 MiB. Replies and tappable status references from 0.5.2 remain.
- Community rows are more like conversation lists: larger photos, member/description previews, verification and unread badges. Joined communities appear first. A My communities filter and an informative request-to-join sheet are included; existing members still open the existing group chat when that navigation is available. No member permissions were relaxed.
- Downloaded post/Reel and channel videos use a shared exporter that burns the Pulse logo/name and creator @username into the MP4, alternating corners every five seconds. If no username is available, the badge uses Made on Pulse. The existing Android Media3 and Windows WinRT native implementations remain. Export failure does not silently save an unwatermarked video. Access is checked again before saving. Channel media has a Download item in its media dropdown. This does not add status/private-chat download tools. Native output appearance, audio retention, cancellation and performance still need Android/Windows testing.
- Settings diagnostics has an authenticated Check LiveKit connection action. The server rate-limits this to three checks per minute/account and checks the LiveKit control API with server credentials. It returns readiness flags only, never keys/room lists. A successful probe does not prove WebRTC media, TURN/NAT behavior, calls or group LIVE works. The nine-seat LIVE Party workflow and existing 100-follower policy remain.

## Backend deployment and security

Script 023_channel_media_status_covers.sql is already applied to the connected Pulse backend. It adds channel attachment metadata, a private channel-media bucket and owner/admin upload policies, publish/history/summary/entry RPCs, a status cover column/RPC and a rate-limited LIVE probe. Existing scripts 001–022 should NOT be rerun. Fresh independent installations use ordered scripts 001–023 once.

pulse-live Edge version 3 is ACTIVE and includes the diagnostic action; it retains custom Auth.getUser/active-account validation and existing party behavior. LiveKit infrastructure/secret readiness was not inspected by reading secrets and is not verified. Use the diagnostic from a signed-in app after building. Do not expose LiveKit/service-role secrets in config.example.json.

New privileged functions live in pulse_private with an empty search_path and explicit authentication/authorization. Public RPC wrappers are invokers with active-account guards; anonymous execution is revoked. Unpublished channel media is restricted to its own uploading admin. Published media checks blocking before granting short-lived signed URLs. Already issued signed URLs/cached images cannot be revoked instantly; new channel media URLs expire after five minutes, status covers after one minute and status media at most one minute/remaining lifetime. Uploads cannot overwrite published objects through client UPDATE grants, and direct cleanup cannot delete linked announcements.

Deployment readback confirmed the history endpoint and channel bucket. Existing records remained at 6 profiles, 21 messages and 2 channel posts after the smoke rollback. Security advisors were unchanged: 30 informational entries for intentionally deny-all private tables and the pre-existing leaked-password-protection warning (https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Local: all 23 ordered schema scripts and all 11 security suites passed, including unknown-size denial, idempotent publication, admin-only upload/publish, protected published media, photo/video/audio metadata, indexed search, stable pagination, blocking, status-cover audience/expiry and LIVE probe rate limits. Node mocked Edge tests passed for party permissions and the new authenticated/rate-limited health action without secret exposure. Native upload transport tests passed for both social and channel buckets, bounded memory, retries, byte integrity and progress. Python helpers: 10 passed, one skipped because CMake is unavailable. Dependency-free Dart upload analysis passed; formatting/parser checks passed.

Connected backend: a transaction tested an authorized channel-video publication, search/media counts and denial of member publishing, then rolled back all fixture data. The first combined schema/test request hit an expired connector request state; a read confirmed nothing was applied, then the smaller schema request and transactional smoke succeeded. No real accounts/messages/posts were edited or verified by these tests. Full Flutter analysis, widget tests, Android/Windows builds, on-device media uploads/playback/recording, watermark exports and two-device RTC remain pending. No APK/EXE was generated here.

## Update and build

1. Extract PULSE_0.5.3_Combined_Update.zip and upload its extracted files/folders to the root of the EXISTING GitHub repository, preserving paths. Commit the replacement files. Do not delete the repository or upload the ZIP as source.
2. Keep existing main.yml/control.yml. No workflow edit or new package is required. The cumulative patch includes earlier fixes; existing CI automatically runs the new schema/security suite through test/isolated_backend/run.mjs.
3. Run Pulse native beta builds for Android APK/Windows installer and Pulse Control staff builds separately. Wait for analysis/tests/builds to pass, then download their artifacts. The Android artifact remains a debug beta, not a signed production release.
4. Test with two accounts: an admin posts a photo, video with cover and voice note; a member views/reacts and cannot publish. Test search across multiple pages, media history, unread badges and reconnect/retry. Upload a new video status and check its cover, reply link, expiration and blocked/outsider access.
5. Download videos from Reels/posts AND channels on Android and Windows. Confirm the Pulse logo/creator name is encoded, changes corner every five seconds, audio remains, cancellation cleans temporary output, and failed export does not produce an unwatermarked download. Try landscape/portrait videos on low-end devices.
6. Run Check LiveKit connection from settings diagnostics. Configure the existing LiveKit server/credentials if needed, then test host + approved audio/video guests and actual calls on separate devices. Staff can adjust the follower requirement for a controlled private test using existing controls; this update does not create fake followers or change the production policy.

This remains a beta. No E2EE claim is made. Real billing, gifts/coins, battles/payouts, full TikTok LIVE parity, automatic updates, production signing and closed-app push/email delivery remain unfinished. The current public build configuration does not configure Firebase client push. Existing access policies and TLS do not replace end-to-end encryption.
